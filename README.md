# Морской бой

Классический «Морской бой» в браузере: игра против бота и сетевая игра вдвоём.
Без сборщика, фреймворков и базы данных — чистый ES-модульный JavaScript, Node.js
и WebSocket. Проект готовится к публикации в Яндекс Играх.

## Возможности

**Два режима игры**

- **Против бота** — полностью офлайн, без сервера. Бот стреляет не наугад:
  после попадания обстреливает соседние клетки вокруг «живого» корабля и
  продолжает поиск, пока не найдёт или не потопит его.
- **По сети** — до двух игроков. Комната по 5-символьному коду или быстрый поиск.

**Расстановка кораблей**

- Перетаскивание мышью, касанием и с клавиатуры (стрелки + Enter/Пробел).
- Поворот корабля, случайная расстановка, полная очистка.
- Корабли нельзя ставить впритык — проверка и по сторонам, и по углам.

**Игровой процесс**

- Ходы по очереди, первый игрок выбирается случайно после расстановки.
- Фиксация промахов и попаданий, отметка потопленных кораблей.
- Журнал боя с координатами и результатами.
- Реванш: оба игрока подтверждают — начинается следующий раунд.
- Звуки генерируются на лету через Web Audio API, файлов-ассетов нет.

**Сетевой режим**

- Устойчивость к обрывам: при переподключении игрок возвращается в бой
  с теми же кораблями и своей очередью хода. Сопернику даётся 60 секунд
  (`DISCONNECT_GRACE_MS`), чтобы вернуться.
- Защита от спама: не более 30 сообщений с восстановлением 12 в секунду.
- Закрытая сессия: комнаты и сессии живут только в памяти процесса.

**Оформление и адаптивность**

- Тёмная тема, безопасные зоны под вырезы экрана, поддержка
  `prefers-reduced-motion`.
- На узких экранах доска соперника и своя переключаются вкладками
  (до 780px или в портретной ориентации).
- Клавиатурная навигация и видимые состояния фокуса.
- Интерактивные элементы — не меньше 44×44 px, чтобы попадать пальцем.

**Интеграция с Яндекс Играми**

- SDK подключается лениво и опционально: без него игра работает полностью,
  просто без рекламы. Таймаут загрузки — 8 секунд.
- Полноэкранная реклама показывается раз в N раундов (по умолчанию 3).
- Запросы на смену полноэкранного режима через SDK.

## Правила игры

Поле 10×10. На нём размещается классический флот:

| Корабль | Размер | Количество |
|---|---|---|
| Линкор | 4 палубы | 1 |
| Крейсер | 3 палубы | 2 |
| Эсминец | 2 палубы | 3 |
| Катерок | 1 палуба | 4 |

Всего 10 кораблей на 20 клетках.

- Корабли **не должны соприкасаться** ни сторонами, ни углами.
- Игроки ходят по очереди, выстрелы мгновенные и без промаха по нескольку
  за ход (классический вариант).
- Первый, кто потопит весь флот соперника, побеждает.
- Первый игрок определяется случайно после того, как оба расставили флот.

## Быстрый старт

Нужен Node.js версии 20 или новее.

```bash
npm install
npm start
```

Откройте <http://localhost:3000> — и выберите режим: «Играть с компьютером»
или «Играть по сети».

### Команды

| Команда | Что делает |
|---|---|
| `npm start` | Запуск сервера на порту 3000 (`0.0.0.0`) |
| `npm run dev` | То же самое с автоперезагрузкой при изменении файлов |
| `npm test` | Прогон всех тестов (`node --test`) |
| `npm run check` | Проверка синтаксиса всех JS/MJS-файлов |

Файл `.env` не обязателен — все настройки имеют значения по умолчанию.
Образец с пояснениями — в `.env.example`.

## Игра по внутренней сети

Сервер сразу слушает `0.0.0.0`, поэтому дополнительно настраивать ничего не нужно.

**На своём компьютере** узнайте адрес в сети:

```bash
ipconfig getifaddr en0     # macOS
hostname -I                 # Linux
ipconfig                    # Windows: IPv4-адрес
```

**Собеседник** открывает в браузере `http://<ваш-адрес>:3000`
(например, `http://10.54.203.17:3000`) — и дальше:

1. Оба жмут «Играть по сети».
2. Первый жмёт «Создать комнату» и называет вслух 5-символьный код.
3. Второй вводит код и жмёт «Войти в комнату».
   Либо оба жмут «Быстрый поиск» — соперник подбирается автоматически.
4. Оба расставляют флот — бой начинается.

Если что-то не подключается:

- Проверьте, что оба в **одной подсети**: `ping <адрес>` с чужой машины.
- Проверьте, не блокирует ли файрвол порт 3000.
- Если браузер показывает 503 или страница не грузится — попробуйте режим
  инкогнито **без расширений**: обычно виноват VPN/adblock-прокси в браузере.
  С рабочей машины проверка: `curl -I http://<адрес>:3000/`.

Приватные адреса (`10.x`, `172.16–31.x`, `192.168.x`, `127.x`, `169.254.x`,
`*.local`) принимаются как корректный источник соединения **только**
при `NODE_ENV=development` — см. [Важные нюансы](#важные-нюансы-прочитайте-при-изменении-кода).

## Как устроен проект

```
server.mjs               Express (статика, /healthz) + WebSocket-сервер
                         комнаты, сессии, очередь быстрого поиска
public/
  index.html             разметка: меню, лобби, игровой экран, оверлей результата
  game.js                клиент целиком: отрисовка canvas, бот, сетевой режим
  platform.js            обёртка над Яндекс SDK: реклама, полный экран, язык
  config.js              рантайм-конфиг, доступен как window.SEA_BATTLE_CONFIG
  styles.css             тёмная тема, адаптив, безопасные зоны
  shared/rules.mjs       ПРАВИЛА: флот, выстрелы, проверки. Используют и сервер, и клиент
tests/
  rules.test.mjs         юнит-тесты правил (расстановка, выстрелы, бот)
  reconnect.test.mjs     интеграционный тест переподключения после обрыва
```

Ключевая идея: **`public/shared/rules.mjs` — один источник правды** для
клиента и сервера. Правила размещения кораблей и обработки выстрелов не могут
разойтись, потому что это буквально один и тот же файл. Он лежит в `public/`,
так как браузер импортирует его напрямую.

Примерно 8200 строк кода, из которых больше половины — клиент.

### Поток сетевой игры

```
Клиент                       Сервер
  │  hello{token}          ──►  создаёт/ищет сессию по анонимному токену
  │  join{action,code}     ──►  находит или создаёт комнату
  │  ◄── state{...}            отдаёт состояние комнаты
  │  place{fleet}          ──►  проверяет флот, ждёт второго игрока
  │  ◄── state{phase:battle}  оба флота на месте — бой начинается
  │  fire{x,y}             ──►  applyAttack на сервере, пересчёт хода
  │  ◄── state{...}            результат выстрела всем в комнате
  │  rematch               ──►  оба подтвердили — новый раунд
```

В сетевом режиме клиент **не доверяет себе**: он не хранит флот соперника
и отправляет только координаты выстрела. Все проверки и подсчёт попаданий
делает сервер — так результат нельзя подделать из браузера.

## Протокол WebSocket

Единая точка входа — `/ws`. Первым обязательно идёт `hello`.

**Клиент → сервер**

| Сообщение | Поля | Назначение |
|---|---|---|
| `hello` | `token` | Регистрация по анонимному токену. `[a-f0-9-]`, 16–80 символов |
| `join` | `action`: `create` \| `join` \| `quick` \| `reconnect`, `code` | Войти, создать комнату, быстрый поиск, вернуться |
| `place` | `fleet` | Отправить расстановку |
| `fire` | `x`, `y` | Выстрел |
| `rematch` | — | Запрос на реванш |
| `leave` | — | Выйти из комнаты |

**Сервер → клиент**

| Сообщение | Поля | Назначение |
|---|---|---|
| `waiting` | `code` | Комната создана, ждём соперника |
| `queued` | — | Идёт быстрый поиск |
| `state` | см. ниже | Полное состояние комнаты |
| `placementAccepted` | — | Флот принят |
| `roomClosed` | `message` | Соперник покинул комнату |
| `error` | `code`, `message` | Ошибка с машиночитаемым кодом |

**Коды ошибок:** `INVALID_TOKEN`, `ALREADY_INITIALIZED`, `NO_SESSION`,
`INVALID_ACTION`, `INVALID_CODE`, `ROOM_FULL`, `ROOM_NOT_FOUND`,
`NOT_IN_ROOM`, `INVALID_PHASE`, `ALREADY_PLACED`, `INVALID_FLEET`,
`NOT_YOUR_TURN`, `OPPONENT_UNAVAILABLE`, `INVALID_ATTACK`, `RATE_LIMIT`,
`INVALID_JSON`, `INVALID_MESSAGE`, `UNKNOWN_MESSAGE`.

### Состав `state`

```jsonc
{
  "type": "state",
  "code": "AB3XY",              // код комнаты
  "round": 1,
  "phase": "placing|battle|finished",
  "self":      { "id": "…", "ready": true, "fleet": [ … ] },
  "opponent":  { "id": "…", "ready": true, "connected": true, "disconnectedAt": null },
  "boards": {
    "self":     { "attacks": [ … ] },
    "opponent": { "attacks": [ … ] }
  },
  "turn":   "self|opponent|null",
  "winner": "self|opponent|null",
  "resultReason": null,
  "rematch": { "self": false, "opponent": false },
  "disconnectDeadline": null,   // до какого ждём вернувшегося
  "events": [ { "text": "…", "at": 1750000000000 } ],
  "serverTime": 1750000000000
}
```

## Важные нюансы (прочитайте при изменении кода)

Здесь собрано то, что уже стоило ошибок. Прежде чем править сетевую часть,
прочитайте этот раздел.

### 1. `boards.self.attacks` — это выстрелы **по своей** доске

Самое неочевидное место проекта. Сервер пишет выстрел в `defender.attacks`
(`server.mjs`, `handleFire`), потому что атакуют именно защитника. Поэтому
`X.attacks` — это список выстрелов, **полученных** игроком X.

Отсюда в `state`:

| Поле | Смысл |
|---|---|
| `boards.self.attacks` | выстрелы **соперника по моей** доске |
| `boards.opponent.attacks` | **мои** выстрелы по доске соперника |

Клиент обязан маппить это **инверсно**: `playerAttacks` ← `boards.opponent`,
`enemyAttacks` ← `boards.self` (`public/game.js`, `applyOnlineState`).
Нарушение этой связи даёт перевёрнутые доски — выстрелы видны не там,
где сделаны, и выглядит это как «игра сломалась».

### 2. Проверка источника соединения

`isOriginAllowed` в `server.mjs`:

- при `NODE_ENV=production` — только явный список `ALLOWED_ORIGINS`
  плюс домены Яндекса;
- в `development` дополнительно `localhost`, `127.0.0.1`, приватные
  диапазоны IPv4 и `*.local`.

Без второй ветки сосед по локальной сети получал `403 Forbidden` на `/ws`:
браузер отправляет `Origin: http://192.168.x.x:3000`, и чисто по «белому
списку» это не проходит. Приватные подсети разрешены **только** вне
production, чтобы не ослаблять продакшн.

### 3. Токен и признак активной комнаты лежат в `sessionStorage`

Ключи `seaBattleToken` и `seaBattleMayHaveRoom` (`public/game.js`).
`sessionStorage` переживает перезагрузку страницы (F5), поэтому возврат в
бой после перезагрузки работает. Но **закрытие вкладки его уничтожает**:
клиент получает `ROOM_NOT_FOUND`, а прежний игрок навсегда занимает второй
слот комнаты в статусе `connected: false` — вернуться в неё по коду уже
нельзя (`ROOM_FULL`). Комната освобождается только через 10 минут уборки.

Также: соединение инициируется **только** из `openOnlineLobby()`. После
перезагрузки нужно снова нажать «Играть по сети» — автоподключения нет.

### 4. `reconnectPlayer` обязан рассылать состояние всей комнате

Используйте `broadcastRoomState(room)`, а не `sendState` только вернувшемуся.
Иначе соперник навсегда останется с `opponent.connected === false`, а клиент
блокирует выстрел при `!opponentConnected` — бой выглядит зависшим, хотя
вернувшийся играет нормально. Поведение закреплено тестом
`tests/reconnect.test.mjs`.

### 5. Комнаты и сессии живут в памяти

`rooms`, `sessions`, `quickQueue` — обычные `Map` и массивы. Одна нода
держит всё состояние; перезапуск сервера обнуляет комнаты. Горизонтальное
масштабирование потребует внешнего хранилища.

## Тесты

```bash
npm test
```

Прогоняются встроенным раннером `node --test`, без внешних зависимостей.

- **`tests/rules.test.mjs`** — юнит-тесты `rules.mjs`: случайный флот
  соответствует раскладке, корабли не соприкасаются, повторный выстрел
  в клетку запрещён, попадание/потопление/промах различаются, бот выбирает
  только необстрелянные клетки.
- **`tests/reconnect.test.mjs`** — интеграционный тест: поднимает настоящий
  сервер на случайном порту, создаёт комнату, расставляет флоты, рвёт сокет
  игрока (имитация перезагрузки страницы), переподключает его с тем же
  токеном и проверяет, что корабли на месте, фаза восстановлена и соперник
  узнал о возвращении.

Тесты на логику сетевого режима проверяют также лимит частоты сообщений:
при автоматизированном прогоне темп должен быть меньше 12 сообщений в секунду
на одно соединение, иначе сервер отвечает `RATE_LIMIT` и закрывает сокет.

## Конфигурация

Все переменные необязательны — есть значения по умолчанию (см. `.env.example`).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт для HTTP и WebSocket |
| `NODE_ENV` | `development` | При `production` включается строгая проверка источника соединения |
| `ALLOWED_ORIGINS` | домены Яндекса | Список разрешённых источников через запятую; `*` отключает проверку |
| `DISCONNECT_GRACE_MS` | `60000` | Сколько ждать вернувшегося соперника после обрыва |
| `CORS_ORIGINS` | пусто | Список origins, которым разрешено читать статику с домена бэкенда; пусто = CORS выключен |

Клиентский конфиг — `public/config.js`:

```js
window.SEA_BATTLE_CONFIG = {
  serverUrl: "",                  // для локальной разработки пусто
  fullscreenAdEveryRounds: 3,
  yandexSdk: undefined            // true/false, по умолчанию автоопределение
};
```

Пустой `serverUrl` означает «подключаться к тому же хосту, откуда загружена
страница». Для Яндекс Игр нужно указать публичный WSS-адрес.

`yandexSdk` управляет загрузкой SDK Яндекс Игр. Без явного значения SDK
грузится только внутри Яндекса, во встроенном iframe или на localhost — на
стороннем сайте эта загрузка не нужна и даёт ошибки в консоли.

## Публикация в Яндекс Играх

1. Задеплоите сервер за HTTPS (обычная платформа или VPS).
2. Укажите публичный адрес в `public/config.js`:

   ```js
   serverUrl: "wss://game.example.ru/ws"
   ```

   Смешивать страницу по HTTP и WebSocket по WSS нельзя — браузер заблокирует
   небезопасное соединение.
3. Задайте `NODE_ENV=production` и перечислите в `ALLOWED_ORIGINS` адрес
   превью и домены Яндекса. При необходимости поднимите `DISCONNECT_GRACE_MS`.
4. Учтите, что комнаты хранятся в памяти процесса: несколько реплик потребуют
   общего состояния (Redis) либо sticky sessions.

## Размещение на своём сайте

Вариант «бэкенд-микросервис в Docker + страница на существующем сайте»
(asolontsov.ru). Пошаговая инструкция — [`deploy/README-deploy.md`](deploy/README-deploy.md).

Коротко:

1. `Dockerfile` — сборка образа бэкенда (Node 22, alpine, непривилегированный
   пользователь, healthcheck на `/healthz`).
2. `docker-compose.yml` — сервис `sea-battle`, публикует **только**
   `127.0.0.1:8102:3000`, наружу порт не выставлен.
3. `deploy/nginx/sea-battle-location.conf` — единственный блок для nginx:
   `location = /sea-battle/ws` с апгрейдом WebSocket (есть варианты для Caddy
   и Traefik). Ассеты проксировать не нужно: фронт автономный.
4. `node scripts/build-site-bundle.mjs` — собирает `dist/sea-battle.html`:
   один самодостаточный файл (стили, склеенный JS, картинка в base64), адрес
   WebSocket считается от `location.host`. Файл копируется в репозиторий
   сайта как `html/games/sea-battle.html`.

Фронт лежит в репозитории сайта, бэкенд — в этом. Обновление игры требует
`node scripts/build-site-bundle.mjs` и копирования результата в сайт;
`dist/` в git не попадает.

## Ограничения

- Нет авторизации и учётных записей — игрок идентифицируется анонимным токеном.
- Комнаты не сохраняются между перезапусками сервера.
- Нет рейтинга, статистики и истории матчей.
- Каталог `.opencode/` — служебные заметки по проекту (архитектура, решения,
  задачи). На игру не влияет.
